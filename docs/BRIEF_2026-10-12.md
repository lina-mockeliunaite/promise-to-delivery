## What exists

- `ledger_fixes.py`: a new version of a source (included in place of the old one; type and date carried over unless changed); a fix as a draft (route, owner, rationale, issues, evidence as specific source versions), then approval. Approved fixes are immutable (database triggers).
- `extraction_cache.py`: the full cache key (content hash, document type, context, prompt, template and schema hashes, model, thinking mode and parameter, max tokens, cache-format version). A hit only when every field matches; a miss calls the frozen `extract.py` function.
- `recheck.py`: a new review after an approved fix (or an unchanged-input rerun without one). Unchanged versions reuse their extraction; a changed extractable version goes through the cache. Consolidation and rules run exactly as in a review. Every existing issue gets one closure check.
- `data/scenarios/`: three revised documents (named exception for Polygon real time; Annex A aligned to real time; an attempted exception for Arbitrum) and `scenarios.json` with the five scenarios and their expected states, written before the recheck code ran on them.
- `scenarios.py`: runs a control (unchanged-input rerun, no model client) and the five scenarios on fresh temporary ledgers. With a scripted extractor: control passes, 5 of 5 as expected, 2 model calls (the revised SOW in S2 and S3).

## How closure works (UNDERSTAND: why a partial fix stays open)

An issue closes only when the recheck **no longer finds it** and its **own closure condition holds with evidence**:

| Issue | Closes when | Evidence cited |
| --- | --- | --- |
| Approval | Authorisation is now standard or an approved exception | The pricing-note version with the named approver |
| Contract gap | The contract chain now includes the promise | The incorporated contract-side version |
| Conflicting terms | The promise is in the contract and the conflicting contract term is gone | The contract-side version |
| Needs evidence | The missing evidence now exists | The version that supplies it |
| Any, if the promise was withdrawn | Every source that made it has a newer included version without it | The replacing versions |

So approval alone leaves the contract gap open (S1), aligning the SOW leaves approval open (S2), and only both close the commitment (S3). "Not raised this time" is never enough: an issue another checker raised (for example the agent) stays open until its condition is met. Excluding a source never closes anything, and reopens what it had closed (the database view already did this). An absolute limit is never closed by an allowed exception (S4), in code and by trigger. A fix with the wrong kind of evidence changes nothing (S5).

## Why the cache key makes a recheck trustworthy (UNDERSTAND)

If a recheck called the model again for unchanged documents, model variation alone could open or close an issue. Reusing the extraction only when every input that can change it is identical means a recheck's changes come from changed evidence, not from the model. An unchanged-input rerun makes no model call and changes no state (tested).

## Decisions taken (logged in DECISIONS.md)

- Identity across reviews: a group keeps the identity of the previous commitment it shares the most (source, quote) statements with; ties by key. A previous commitment with no statement left is recorded as unsupported, never deleted.
- Development rechecks carry forward the previous review's extraction for an unchanged source version (same version id, same text). The imported run-file rows stay non-reusable by key; this is reuse by version identity, not a cache hit.
