## Rules-vs-agent decision rule (capability and authorisation only)

Written 3 Oct, before any agent code exists. The agent is kept for the app only if **all three** hold over the 5 Oct development runs (Harbour Bank and hard cases, three fresh agent runs each, against the same ledger):

1. **Adds a material conflict.** It raises at least one material issue (an approval issue or an absolute limit) that the rules miss, and that issue matches a labelled issue. A finding the labels do not support counts against it (condition 2), not for it.
2. **No unsupported findings and no uncited verdicts.** In all three runs, every verdict cites a catalogue path or a pricing-note line that exists, and no issue is raised that the labels contradict.
3. **Within the bounds below.**

| Bound | Limit | Measured as |
| --- | --- | --- |
| Extra cost per deal review | ≤ $0.10 (about 1.5× today's extraction, $0.068) | Mean of three runs; no single run above $0.20 |
| Extra latency per deal review | ≤ 60 seconds | Mean wall-clock time of three runs; no single run above 120 s |
| Tool calls | ≤ 6 per commitment, ≤ 40 per deal | Hard cap in the agent loop; a capped run counts as a failure |
| Variation | Recorded, not a condition | Verdicts that differ across the three runs, per commitment |

If any condition fails, the rules power the demo and the README says why. Both implementations stay in the repo. Budget check: three runs on two deals at the upper bound is $1.20 against $19.79 credit.

## Why rules are enough for some conflicts (UNDERSTAND, for Monday)

- The catalogue is complete and structured: region → network → asset → mode, with status, sellability and limits. "Is Polygon real-time standard in Singapore?" is a lookup, not a judgement.
- Once a promise is parsed into terms, the conflict check is a comparison: same capability and network, different mode; or a number above a limit. Comparisons are deterministic, free and repeatable: the same inputs give the same findings every time, which is what makes a recheck trustworthy.
- Every rule verdict cites its evidence: the catalogue path and the pricing-note line. An auditor can check it without trusting a model.
- Rules fail where wording varies beyond the vocabulary (paraphrases, unlisted services such as a weekly meeting). They say *needs review* there instead of guessing. That gap is exactly what the 5 Oct agent comparison measures.
- The design principle: use a model where language is ambiguous (extraction), and rules where the reference data is authoritative (authorisation, coverage).
