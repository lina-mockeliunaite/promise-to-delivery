## Design: escalation, not replacement (UNDERSTAND: workflow vs agent)

- The rules run first on everything. Only firm commitments the rules leave as *unknown / needs review* go to the agent (7 on the practice set, 1 on Harbour Bank, 1 on hard cases).
- **The agent interprets language; code checks evidence.** The agent proposes terms in catalogue language ("instant risk check" → real-time screening on Polygon), each backed by a phrase copied from the quote or its neighbouring paragraph, plus a catalogue path and a pricing-note line. Code recomputes the verdict from those terms with the same rule functions. A verdict its own evidence does not support, or that cites nothing, is rejected and counted against the agent.
- **The loop** (UNDERSTAND: the agent loop): the model reads the task, calls tools (`search_catalogue`, `get_capability`, `get_pricing_note`), reads the results, and calls `submit_verdict` once per commitment; the code runs each tool and returns the result; repeat until every commitment has a verdict or a bound is hit.
- **Bounds:** 6 tool calls per escalated commitment, 40 per deal, 15 turns. Hitting one ends the run as *capped*, which fails condition 3.
- Same model as extraction (`config.AGENT_MODEL`), so the comparison is about the method, not the model.
- The agent never reads labels, briefs or fingerprint files; it does not write the ledger. Results go to `results/agent_compare_<timestamp>.json`.

## How it is judged (fixed 3 Oct, before the run)

1. **Adds a material issue:** an accepted approval issue (including an absolute limit) on a labelled commitment where the rules raised none.
2. **No unsupported or uncited verdict in any run:** an accepted approval issue the labels do not support, a rejected verdict that claimed more than *unknown*, or a verdict with no catalogue path, each fails it.
3. **Within bounds:** mean extra cost ≤ $0.10 and mean latency ≤ 60 s per deal review over three runs, no run above twice either, none capped.

Keep the agent only if all three hold. Otherwise the rules power the demo and the README says why. Disclosed bias: Claude wrote the practice set knowing the rules' blind spots.
